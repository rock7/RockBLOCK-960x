Detailed Description

RockBLOCK 9602 / 9603 / 9604 driver: public API.

This is the only header applications include. Everything declared here must be plain C99 and free of platform headers: no <windows.h>, <unistd.h> or Arduino.h.

Design rules (these are what keep the library portable):

  • No heap. The caller owns the rb960x_t context, which holds the AT line buffer; the library never calls malloc().
  • No direct OS or I/O calls. All UART and clock access goes through atPort_t callbacks: the platform's port, opened by rb960xBegin(), or ones the caller passes to rb960xInit().
  • Fixed-width <stdint.h> types where size matters, since int is only 16 bits on AVR.

Model support: some functions only work on certain models, or (on the 9604) only in a certain radio access technology (RAT) mode. These return RB960X_ERR_INVALID_MODEL or RB960X_ERR_WRONG_RAT rather than sending a command the modem would reject.

◆ rb960xSessionCallback_t

typedef void(* rb960xSessionCallback_t) (struct rb960x *rb, rb960xStatus_t status, const rb960xSessionResult_t *result, void *userData)

Called when an asynchronous rb960xInitiateSessionAsync() finishes.

Runs from inside rb960xProcess(). The session has already been cleared, so the callback may start another one.

Parameters
rbThe context the session ran on.
statusThe result rb960xInitiateSession() would have returned: RB960X_OK if the session worked (MO status 0 to 4), RB960X_ERR_SESSION if it ran but failed, RB960X_ERR_TIMEOUT or RB960X_ERR_PROTOCOL otherwise.
resultThe session result when status is RB960X_OK or RB960X_ERR_SESSION, otherwise NULL. Only valid during the callback; copy it to keep it.
userDataThe pointer given to rb960xInitiateSessionAsync().

◆ rb960xModuleFunc_t

enum rb960xModuleFunc_t

Module functionality level, set with rb960xAtCfun() (AT+CFUN=<fun>).

Enumerator
RB960X_CFUN_0 

Minimum functionality: transmit and receive RF circuits are turned off (both CS and PS services deactivated).

RB960X_CFUN_1 

Full functionality (the factory default), e.g. to come out of airplane mode or minimum functionality. Persists across power cycles triggered by AT+CFUN=15, AT+CFUN=16 or AT+CPWROFF (where supported).

RB960X_CFUN_4 

Airplane mode: transmit and receive RF circuits are turned off (both CS and PS services deactivated). Persists across power cycles triggered by AT+CFUN=15, AT+CFUN=16 or AT+CPWROFF (where supported).

RB960X_CFUN_10 

Fast power-off: shuts down without sending a network detach request, saving the current settings to non-volatile memory. "OK" means the request was accepted; the +UUFASTSHUTDOWN URC then reports how the power-off went.

RB960X_CFUN_16 

Silent reset of the module and the SIM card, with network detach and NVM parameters saved first.

◆ rb960xMoStatus_t

enum rb960xMoStatus_t

The +SBDIX MO status, decoded for the modem's model; see rb960xSessionResult_t::moResult and rb960xMoStatusText().

Both AT command guides number the codes the same way, but the 9602/9603 guide defines more of them. A code is only given its own name on the models whose guide defines it. On other models it becomes one of the RB960X_MO_RESERVED_* values, as that model's guide describes it.

Named values equal the raw code. The RB960X_MO_RESERVED_* values are above 255, so they never match a raw code; the raw code is still in rb960xSessionResult_t::moStatus.

Enumerator
RB960X_MO_OK 

0: MO message, if any, sent. All models.

RB960X_MO_OK_MT_TOO_BIG 

1: MO message, if any, sent, but the queued MT message was too big to transfer. 9602/9603 only.

RB960X_MO_OK_LOCATION_UPDATE_REJECTED 

2: Session completed, but the requested location update was not accepted. All models.

RB960X_MO_GSS_CALL_TIMEOUT 

10: The gateway reported that the call did not complete in the allowed time.

RB960X_MO_GSS_QUEUE_FULL 

11: The MO message queue at the gateway is full.

RB960X_MO_TOO_MANY_SEGMENTS 

12: The MO message has too many segments.

RB960X_MO_GSS_SESSION_INCOMPLETE 

13: The gateway reported that the session did not complete.

RB960X_MO_INVALID_SEGMENT_SIZE 

14: Invalid segment size.

RB960X_MO_ACCESS_DENIED 

15: Access is denied. All models.

RB960X_MO_LOCKED 

16: The modem is locked and may not make SBD calls (see AT+CULK). All models.

RB960X_MO_GATEWAY_NOT_RESPONDING 

17: Gateway not responding (local session timeout). All models.

RB960X_MO_RF_DROP 

18: Connection lost (RF drop). All models.

RB960X_MO_LINK_FAILURE 

19: Link failure (a protocol error ended the call). 9602/9603 only.

RB960X_MO_NO_SERVICE 

32: No network service, unable to initiate call. All models.

RB960X_MO_ANTENNA_FAULT 

33: Antenna fault, unable to initiate call. All models.

RB960X_MO_RADIO_DISABLED 

34: Radio is disabled, unable to initiate call (see AT*Rn). All models.

RB960X_MO_BUSY 

35: The modem is busy, unable to initiate call. All models.

RB960X_MO_WAIT_REGISTRATION 

36: Try later, must wait 3 minutes since the last registration. All models.

RB960X_MO_SERVICE_DISABLED 

37: SBD service is temporarily disabled. All models.

RB960X_MO_TRAFFIC_MANAGEMENT 

38: Try later, traffic management period (see AT+SBDLOE). All models.

RB960X_MO_BAND_VIOLATION 

64: Band violation (tried to transmit outside the permitted band). 9602/9603 only.

RB960X_MO_HARDWARE_ERROR 

65: Hardware error during the transmit (the 9602/9603 guide says PLL lock failure). All models.

RB960X_MO_RESERVED_SUCCESS 

9602/9603: 3 or 4 ("reserved, but indicate MO session success"). 9604: 1, which its +SBDIX list leaves out.

RB960X_MO_RESERVED_LOCATION_UPDATE_FAILURE 

9604 only: 3 to 14 ("reserved, but indicate location update failure").

RB960X_MO_RESERVED_FAILURE 

Any other code the model's guide doesn't define ("reserved, but indicate failure").

The signal is below RB960X_MIN_SIGNAL_BARS, so a session isn't worth attempting yet.

◆ rb960xInit()

rb960xStatus_t rb960xInit ( rb960x_t *  rb,
const atPort_t *  port,
atDebugHandler_t  debugHandler,
void *  debugUserData 
)

Initialise a driver context and identify the connected modem.

Steps, stopping at the first failure:

  1. Set up the AT client and debug handler.
  2. Send "AT" until the modem responds, up to RB960X_INIT_ATTEMPTS times.
  3. Turn command echo off (ATE0).
  4. Read the model (ATI7).
  5. Read the IMEI (AT+CGSN). On the 9604 this is the cellular IMEI.
  6. Read the serial number: AT+GSN, or on the 9604, AT+USATSN, which also gives the satellite IMEI.
  7. 9604 only: read the current RAT mode (AT+URAT?), then switch to RB960X_INIT_RAT with rb960xSwitchRat() unless it is RB960X_INIT_RAT_NONE (the default is SBD). A switch resets the module, so it comes before the settings below.
  8. Set the DTR option (AT&D) and flow control (AT&K) from rockblock960x_config.h.
  9. Enable the SBDRING ring alert URC: AT+SBDMTA=1, or on the 9604 AT+URING=1.

Use this to supply your own port callbacks (an RTOS, a custom UART, a test mock); otherwise rb960xBegin() is simpler.

Parameters
[out]rbContext to initialise. Cleared before use.
[in]portPlatform callbacks. Must stay valid for as long as rb is used (see atPort_t).
[in]debugHandlerOptional AT traffic trace (NULL to disable). It is set up before the first "AT" so it also shows rb960xInit()'s own commands. See atClientSetDebugHandler().
[in]debugUserDataPassed back to debugHandler.
Returns
RB960X_OK on success, otherwise the error from the step that failed. If ATI7 doesn't report a recognised model, rb->model is left as RB960X_MODEL_UNKNOWN.

rb960xStatus_t rb960xInitiateSession ( rb960x_t *  rb,
bool  answerRing,
uint32_t  timeoutMs,

Initiate an SBD session and wait for it to finish (AT+SBDIX).

Sends whatever is in the MO buffer (nothing if it is empty) and checks the gateway for MT messages, in one session. Every session can cost credits. Makes one attempt; on RB960X_ERR_SESSION the result's moResult says why, so the application can decide whether and when to try again.

Sets the modem's session timeout to RB960X_SBD_SESSION_TIMEOUT_S (AT+SBDST) first, as the modem forgets it at power-up.

A session empties the modem's MT buffer, so while an MT message is waiting there unread this returns RB960X_ERR_MT_UNREAD without starting one. Read it with rb960xReadMtBuffer() (or discard it with rb960xClearBuffers()) first.

[in]timeoutMsHow long to wait for the session, in milliseconds. RB960X_SBDIX_TIMEOUT_MS is a sensible default; keep it longer than RB960X_SBD_SESSION_TIMEOUT_S so the modem's own timeout ends a stalled session first.
[out]resultFilled with the session result when the return is RB960X_OK or RB960X_ERR_SESSION, zeroed otherwise. May be NULL.

◆ rb960xProcess()

void rb960xProcess ( rb960x_t *  rb)

Service the modem: dispatch URCs, finish asynchronous sessions and poll the signal.

Never blocks for long. Each call does one of:

  • If an asynchronous session is running: checks whether it has finished (or timed out) and, if so, calls its callback.
  • Otherwise: reads any pending modem output and dispatches URCs (notably SBDRING, which sets rb960x_t::ringAlert), calls the ring callback if a ring alert is waiting to be reported, then, if a signal callback is set, a poll is due and the ring callback didn't start an asynchronous session, sends AT+CSQF and calls the signal callback.

Call this regularly from the application's main or idle loop.

[in,out]rbInitialised context. Does nothing if NULL.

◆ rb960xSetRingCallback()

void rb960xSetRingCallback ( rb960x_t *  rb,
rb960xRingCallback_t  callback,
void *  userData 
)

Have rb960xProcess() report SBDRING ring alerts.

A ring alert means the gateway has an MT message waiting. The driver always records it in rb960x_t::ringAlert; this callback is an optional way to hear about it instead of checking that field.

The callback runs from rb960xProcess(), not when the SBDRING line arrives: a ring alert can arrive in the middle of another command, so it is held until the next rb960xProcess() that isn't finishing an asynchronous session. It is skipped if a session has reached the gateway in the meantime (which answers the ring). It is called once per SBDRING; the gateway may repeat a ring alert until it is answered. A ring alert that arrived before the callback was set is reported on the next rb960xProcess().

The callback may start a session, e.g. rb960xInitiateSession(rb, true, ...) or rb960xInitiateSessionAsync(rb, true, ...), which costs credits; the driver never answers a ring by itself.

Call after rb960xInit(), which clears the callback.

Parameters
[in,out]rbInitialised context. Does nothing if NULL.
[in]callbackCalled after each ring alert, or NULL for none.
[in]userDataPassed back to callback.

Turns the radio off (AT+CFUN=0), selects the new RAT (AT+URAT), then resets the module (AT+CFUN=16).
