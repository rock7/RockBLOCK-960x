Detailed Description

rb960xBegin() and rb960xEnd(): rb960xInit() on the platform's serial port.

Kept out of rockblock960x.c because these call atPortOpen(), which only exists where a port is built in (atclient_port in CMake, or the Arduino port). Builds that supply their own callbacks, like the unit tests and the Python bindings, leave this file out and use rb960xInit().

Open the serial port and initialise the modem on it.

The usual way to start: opens device with the platform's port (see at_port.h) inside rb, then runs the same steps as rb960xInit(). Call rb960xEnd() when finished. Use rb960xInit() instead to supply your own port callbacks.

On Arduino, call begin() on the serial port first and use the rb960xBegin(rb, Serial1) overload below; baud is ignored there.

Needs the platform's port linked in (atclient_port in CMake; built in automatically on Arduino and PlatformIO).

Parameters
[out]rbContext to initialise. Cleared before use.
[in]deviceWhat to open, e.g. "/dev/ttyUSB0" (see atPortDevice_t).
[in]baudBaud rate (see atPortOpen()).
[in]debugHandlerOptional AT traffic trace (NULL to disable). See rb960xInit().
[in]debugUserDataPassed back to debugHandler.
Returns
RB960X_OK on success, RB960X_ERR_ARG if rb is NULL, RB960X_ERR_PORT if the port couldn't be opened, or the error from rb960xInit(). On any failure the port is closed again.

rb960xStatus_t rb960xEnd ( rb960x_t *  rb)

Close the serial port rb960xBegin() opened.

Safe to call more than once, after a failed rb960xBegin(), or after rb960xInit() (which owns no port, so there is nothing to close). The context can't be used again until the next rb960xBegin() or rb960xInit().

[in,out]rbContext to close.
Returns
RB960X_OK, or RB960X_ERR_ARG if rb is NULL.
